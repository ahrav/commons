# `protected-write-set-is-fence-complete`

- **Discovery:** targeted consumer write-surface pass after portfolio evaluation.
- **Primary evidence:** SQLite documents `with_conn` as unfenced and read-only by contract but cannot enforce that restriction (`cortexkit-store/src/lib.rs:140-153`). PostgreSQL exposes enforced read-only and fenced transactions (`cortexkit-store-postgres/src/lib.rs:84-107,109-126`) plus an explicitly unfenced autocommit callback for statements a transaction block forbids (`:128-147`). Both migration implementations check the fence in the same transaction as schema SQL (`cortexkit-store/src/lib.rs:390-454`; `cortexkit-store-postgres/src/lib.rs:320-367`).
- **Discriminating fact:** each backend retains exactly one unfenced durable-write surface, and neither is enforceable by its engine. `with_conn` is unfenced because SQLite cannot reject writes on a read-only contract; `with_client_unfenced` is unfenced because PostgreSQL forbids `VACUUM` and the `CONCURRENTLY` index forms inside a transaction block, so the fenced and read-only callbacks cannot carry them.
- **Existing evidence:** the [durable consumer inventory](../durable-consumer-inventory.md) records unfenced durable mutations in Magic Context. Backend tests cover fenced writes, migrations, rollback, PostgreSQL read-only enforcement, and that the unfenced callback reaches statements a transaction rejects (`cortexkit-store-postgres/src/lib.rs:465-485`); none covers consumer completeness.
- **Failure scenario:** domain code performs a protected durable mutation through an unfenced closure or migration path.
- **Timing window:** stale connection after handover.
- **Instrumentation:** authoritative inventory of durable-write sites plus at least one authoritative fence check atomically bound to each protected commit.
- **Open-question log:** companion SQLite consumer migrations and an authoritative protected write-set classification remain unavailable. Whether maintenance statements through `with_client_unfenced` count as protected writes needs the same owner.
