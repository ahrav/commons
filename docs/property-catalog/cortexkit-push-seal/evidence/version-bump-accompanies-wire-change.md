# Evidence: `version-bump-accompanies-wire-change`

- Discovery lenses: lifecycle transitions, version compatibility, bug history.
- Trigger: docs call the crate version the only signal a path consumer receives.
- Code trail: the module docs state the bump rule; `[package] version` and `publish = false` in `Cargo.toml`; the workspace publishing rule in `README.md`.
- Implemented mechanism: `tests/golden/push-seal-wire-v1.json` freezes one deterministic local envelope and all four local `OpenError` classifications. `tests/version_gate.rs` compares the fixture's represented wire surface (`schema_version`, `ciphersuite`, `inputs`, `expected`) at the merge base against the head revision and requires an increased package version when it changes; provenance prose, build-identity metadata, and JSON formatting are excluded.
- Failure scenario: source or dependency changes emitted bytes or acceptance behavior while self-roundtrip tests stay green and version remains `0.1.0`.
- Timing/configuration: pull requests run the actual merge-base comparison on Ubuntu with event SHAs. Local, push, and `workflow_call` runs execute synthetic policy cases without claiming an actual revision comparison; the CI step also fails when the gate test does not run.
- Existing evidence: synthetic tests reject a represented wire-surface change with an unchanged or decreased version, accept the same change with an increased version, accept initial fixture bootstrap, ignore provenance-prose, formatting, and unrelated changes, and fail closed on an unparseable fixture. The actual gate fails on unreadable revisions and on git failures other than proven path absence.
- Audit: audited only for changes represented by the committed fixture. Source changes that preserve the fixture, unrepresented behavior, and external opener compatibility remain unaudited.
- Instrumentation: the fixture records schema version, synthetic test-only provenance, suite and mode, empty `info`, version AAD, plaintext, exact envelope, dependency/build identity, and represented classifications. `wire_v1_fixture_matches_local_bytes_and_classifications` asserts the recorded dependency versions against `Cargo.lock`, anchors every classification case to the verified envelope, and requires all four public classifications to be represented.
- Investigation log: no independent opener corpus exists in this repository. The frozen bytes are a local regression oracle only.
