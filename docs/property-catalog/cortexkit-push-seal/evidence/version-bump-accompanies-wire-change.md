# Evidence: `version-bump-accompanies-wire-change`

- Discovery lenses: lifecycle transitions, version compatibility, bug history.
- Trigger: docs call the crate version the only signal a path consumer receives.
- Code trail: the module docs state the bump rule; `[package] version` and `publish = false` in `Cargo.toml`; the workspace publishing rule in `README.md`.
- Implemented mechanism: `tests/golden/push-seal-wire-v1.json` freezes one deterministic local envelope and all four local `OpenError` classifications. `tests/version_gate.rs` compares the fixture's represented wire surface (`schema_version`, `ciphersuite`, `inputs`, `expected`) at the merge base against the head revision against the head revision and, for each of the merge base and the base-branch tip whose surface differs from the head's, requires the head package version to exceed that revision's; a revision without the fixture or already carrying the head's surface constrains nothing; provenance prose, build-identity metadata, and JSON formatting are excluded. Comparison follows SemVer precedence including prerelease identifiers, and build metadata carries no precedence. Numeric prerelease identifiers are held as digits and ordered by digit count then lexically, so identifiers wider than any fixed integer type still order by value; an empty or leading-zero identifier fails the gate instead of ordering under a guess. The manifest is deserialized as TOML rather than matched line by line, so every spelling Cargo reads as `[package] version` -- quoted or dotted keys, either string style, escape sequences, comments, multi-line strings -- reads as one value; an unreadable manifest or an unparseable version fails the gate rather than passing. A version inherited through `version.workspace = true` is reported as an unsupported configuration rather than as a missing version, since resolving it requires the root manifest at the same revision and this gate reads only the crate manifest.
- Failure scenario: source or dependency changes emitted bytes or acceptance behavior while self-roundtrip tests stay green and version remains `0.1.0`.
- Timing/configuration: pull requests run the actual merge-base comparison on Ubuntu with event SHAs. Local, push, and `workflow_call` runs execute synthetic policy cases without claiming an actual revision comparison; the CI step also fails when the gate test does not run.
- Existing evidence: synthetic tests reject a represented wire-surface change with an unchanged or decreased version, accept the same change with an increased version, accept initial fixture bootstrap, ignore provenance-prose, formatting, and unrelated changes, and fail closed on an unparseable fixture. Further tests hold the read version constant across manifest formatting variants, gate a wire change whose version is commented or literal-quoted, fail closed on an unparseable version, order prerelease versions by SemVer precedence in both directions, order 20- and 21-digit numeric prerelease identifiers by value in both directions and against an alphanumeric identifier, fail closed on empty and leading-zero prerelease identifiers, fail closed on an unreadable manifest, on a manifest with no `[package] version`, on a non-string version, and on a workspace-inherited version, name which of the four sections moved in the failure text, reject a version already taken on the base-branch tip for a different surface, and accept an equal version when the base tip already carries the head's surface. The actual gate fails on unreadable revisions and on git failures other than proven path absence, and returns without comparing when the merge base predates the fixture.
- Audit: audited only for changes represented by the committed fixture. Source changes that preserve the fixture, unrepresented behavior, and external opener compatibility remain unaudited.
- Instrumentation: the fixture records schema version, synthetic test-only provenance, suite and mode, empty `info`, version AAD, plaintext, exact envelope, dependency/build identity, and represented classifications. `wire_v1_fixture_matches_local_bytes_and_classifications` resolves each recorded dependency by walking this crate's own dependency edges from its `Cargo.lock` entry, rather than by name across the whole lock file, and fails when the crate reaches more than one version of a recorded name, anchors every classification case to the verified envelope, and requires all four public classifications to be represented.
- Investigation log: no independent opener corpus exists in this repository. The frozen bytes are a local regression oracle only.
