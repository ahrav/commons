# Evidence: `version-bump-accompanies-wire-change`

- Discovery lenses: lifecycle transitions, version compatibility, bug history.
- Trigger: docs call the crate version the only signal a path consumer receives.
- Code trail: the module docs state the bump rule; `[package] version` and `publish = false` in `Cargo.toml`; the workspace publishing rule in `README.md`.
- Implemented mechanism: `tests/golden/push-seal-wire-v1.json` freezes one deterministic local envelope and all four local `OpenError` classifications. `tests/version_gate.rs` compares the fixture's represented wire surface (`schema_version`, `ciphersuite`, `inputs`, `expected`) at the head with the merge base and base-branch tip. Each prior revision whose surface differs from the head requires a higher head package version; a revision without the fixture or already carrying the head's surface constrains nothing. Provenance prose, build-identity metadata, and JSON formatting are excluded. Manifests are parsed as TOML, and package versions are parsed with `semver::Version::parse` and compared with `Version::cmp_precedence`. This applies SemVer prerelease ordering and ignores build metadata for precedence. Malformed versions fail the gate. A version inherited through `version.workspace = true` is reported as an unsupported configuration because the gate reads only the crate manifest.
- Failure scenario: source or dependency changes emitted bytes or acceptance behavior while self-roundtrip tests stay green and version remains `0.1.0`.
- Timing/configuration: pull requests run the actual merge-base comparison on Ubuntu with event SHAs. Local, push, and `workflow_call` runs execute synthetic policy cases without claiming an actual revision comparison; the CI step also fails when the gate test does not run.
- Existing evidence: `synthetic_version_gate_cases` covers unchanged, increased, decreased, bootstrap, provenance-only, formatting-only, and malformed-fixture cases. `manifest_spellings_parse_equally_and_still_enforce_the_gate` checks Cargo-compatible TOML spellings and confirms each still gates a wire change. `an_unparseable_version_fails_the_gate` covers malformed head and prior versions. `prerelease_versions_compare_by_semver_precedence` checks increasing and decreasing prerelease precedence, release-versus-prerelease ordering, and build metadata equality. Other tests cover missing wire sections, unreadable or unsupported manifests, changed-section diagnostics, base-tip version reuse, and a base tip that already carries the head surface. `actual_git_diff_requires_version_bump` fails on unreadable revisions and Git errors other than proven path absence, and skips comparison when the merge base predates the fixture.
- Audit: audited only for changes represented by the committed fixture. Source changes that preserve the fixture, unrepresented behavior, and external opener compatibility remain unaudited.
- Instrumentation: the fixture records schema version, synthetic test-only provenance, suite and mode, empty `info`, version AAD, plaintext, exact envelope, dependency/build identity, and represented classifications. `wire_v1_fixture_matches_local_bytes_and_classifications` resolves each recorded dependency by walking this crate's own dependency edges from its `Cargo.lock` entry, rather than by name across the whole lock file, and fails when the crate reaches more than one version of a recorded name, anchors every classification case to the verified envelope, and requires all four public classifications to be represented.
- Investigation log: no independent opener corpus exists in this repository. The frozen bytes are a local regression oracle only.
