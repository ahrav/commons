# Evidence: `byte-determining-dependency-closure-is-pinned`

- Discovery lenses: dependencies, build configuration, lifecycle transitions.
- Trigger: dependency drift can change bytes even when crate source and package version do not change.
- Code/config trail: `crates/cortexkit-push-seal/Cargo.toml` requires `hpke = "0.14"` and `getrandom = "0.4"` with `default-features = false` and explicit feature sets. The tracked workspace `Cargo.lock` records resolved versions, sources, checksums, and dependency edges. Cargo commands in `.github/workflows/ci.yml` use `--locked`, so CI rejects a resolution that would rewrite the lockfile. `wire_v1_fixture_matches_local_bytes_and_classifications` regenerates one exact local envelope from fixed synthetic key material and entropy and checks represented errors. This catches byte or classification drift for that vector, but the fixture does not record or independently validate the dependency closure.
- Resolution fact: manifest requirements cannot record a closure. Exact `=` requirements were tried and rejected: they make one version the only satisfiable one, so they block entropy and crypto patch releases and turn a path consumer that needs a newer in-range patch into a resolution failure rather than an upgrade. They also leave the transitive graph floating, so they buy no reproducibility. The tracked lockfile plus `--locked` is the mechanism for default-CI resolution.
- Default-CI identity: the manifest constrains direct versions and declares feature sets. The lockfile pins the workspace's resolved version-and-checksum closure, including implementation crates below the direct wrappers. Locked CI rejects resolution that would change that file.
- Negative control: in a temporary workspace copy, changing the push-seal `getrandom` requirement from `=0.4.3` to `=0.4.2` made `cargo test --locked -p cortexkit-push-seal --no-run` fail because `--locked` prevented a lockfile update. The canonical manifest and lockfile SHA-256 hashes were unchanged.
- Build-identity scope: default CI uses the manifest's declared features and the workspace resolution in the tracked lockfile. No checked artifact records the activated feature graph, target triple, `getrandom_backend` configuration, or full transitive closure for each build purpose.
- Competing explanation: suite-codepoint assertions might make resolution drift harmless. They cannot detect a same-codepoint serialization, key-schedule, clamping, or RNG-wrapper behavior change.
- Failure scenario: two fresh builds of one crate revision use different crypto closures and produce different bytes or classifications while local source and version remain unchanged.
- Timing/configuration: dependency publication between builds; workspace feature unification.
- Existing evidence: locked focused tests, workspace lint, workspace tests, and the live PostgreSQL CI command consume the committed workspace resolution. The local byte fixture pins one exact envelope and represented error classifications. The negative control proves the lock gate rejects manifest drift instead of silently rewriting the lockfile.
- Remaining gap: the lockfile and manifest do not audit target-specific activated features or entropy backends, alternate path consumers, the external opener, or identities for deterministic-vector, entropy-failure, release, and other build purposes. The broad property is not fully audited.
- Future instrumentation: record and compare `cargo metadata`, activated feature graph, target triple, build purpose, and `getrandom_backend` configuration before claiming per-purpose dependency identity.
- Investigation log: the unused direct `rand_core 0.9` requirement was removed and direct `getrandom` was added so `seal` can name `SysRng`. hpke's `getrandom` feature moved to `[dev-dependencies]`; the library reaches only `alloc`-gated HPKE entry points, so the shipped library no longer compiles hpke's own ambient-RNG selection. The `hex` dev dependency does not enter emitted bytes. Floating stable Rust was examined and excluded from this wire-identity property; absent a compiler defect, toolchain identity does not define HPKE wire bytes.
